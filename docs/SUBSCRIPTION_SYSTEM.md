# Система управления доступом (подписки) для WireGuard

Идея: управлять доступом к VPN без захода на сервер — добавлять пользователей, задавать срок подписки, отключать по истечении срока. Варианты: веб-панель или бот (Telegram и т.п.).

---

## 1. Что нужно реализовать

| Функция | Описание |
|--------|----------|
| **Добавление пользователя** | Создание пары ключей, запись Peer в конфиг WG, выдача .conf или QR |
| **Срок подписки** | Хранить дату окончания доступа; по истечении — удалять Peer или отключать |
| **Удаление / отключение** | Убрать Peer из конфига или помечать как неактивного |
| **Без захода на сервер** | Всё через API/скрипты: панель или бот дергают скрипты на VPS (по SSH или агент на сервере) |

Дополнительно (по желанию): продление подписки, лимиты по трафику, несколько тарифов.

---

## 2. Архитектура в двух словах

```
[Ты]  →  Веб-панель или Бот  →  Сервер (VPS)
                                      ↓
                              Скрипты на VPS:
                              - добавить peer
                              - удалить peer
                              - выдать конфиг
                              + cron: отключение по дате
```

Логика «подписка истекла» может жить:
- в **БД** (SQLite/PostgreSQL) на том же VPS или на отдельной машине;
- панель/бот читают БД и вызывают скрипты на VPS (по SSH или через маленький API на самом VPS).

---

## 3. Вариант A: Веб-панель

**Плюсы:** удобно с компьютера, можно дать доступ доверенным людям, история, статистика.  
**Минусы:** нужен хостинг под панель, HTTPS, авторизация.

**Стек (пример):**

- **Бэкенд:** Python (FastAPI/Flask) или Node.js на том же VPS или отдельном.
- **БД:** SQLite (проще) или PostgreSQL — пользователи, дата окончания подписки, публичный ключ, внутренний IP.
- **Связь с VPS WireGuard:**  
  - либо панель стоит на том же VPS и вызывает локальные скрипты (добавить/удалить peer, сгенерировать конфиг);  
  - либо по SSH (paramiko и т.п.) выполняешь команды на VPS;  
  - либо на VPS крутится маленький **API** (например FastAPI), который изнутри вызывает те же скрипты — панель дергает этот API по токену.

**Логика подписки в коде:**

- При «добавить пользователя»: создать ключи, записать peer в `/etc/wireguard/wg0.conf` (или через `wg set`), сохранить в БД: user_id, public_key, allowed_ip, date_end.
- **Cron на VPS** (раз в день): скрипт смотрит БД, находит записи с `date_end < today`, для каждой удаляет peer из WG и помечает пользователя как отключённого (или удаляет из конфига).
- В панели: форма «добавить пользователя» + срок; кнопка «выдать конфиг»/«показать QR» (генерируешь .conf из шаблона и отдаёшь или показываешь QR).

Готовые панели в духе **WireGuard UI** (например, wg-easy, subspace и др.) часто уже умеют добавлять peer и показывать QR; доработка под «срок подписки» — свой cron + БД или поля в их БД, если есть.

---

## 4. Вариант B: Бот (Telegram и др.)

**Плюсы:** не нужен сайт, всё в мессенджере, быстро поднять.  
**Минусы:** управление только через бота; для выдачи конфигов нужно аккуратно (не светить ключи в логах).

**Логика:**

- Команды типа: «Добавить пользователя», «Выдать конфиг», «Продлить на N дней», «Список пользователей», «Отключить пользователя».
- Бот хранит состояние/БД (SQLite достаточно): пользователь, дата окончания, внутренний IP, привязка к публичному ключу.
- Для «физического» добавления peer на VPS бот может:
  - по SSH выполнять скрипты на VPS (add_peer.sh, remove_peer.sh), или
  - слать запросы на твой маленький API на VPS (как в варианте A).

Тот же **cron на VPS** раз в день отключает peer’ов с истёкшей подпиской (скрипт читает БД или список «кого отключить» от бота/API).

**Безопасность бота:** только ты (или доверенные админы по user_id) имеете право на команды добавления/удаления; конфиги и ключи в чат не логировать в открытом виде, лучше отдавать файлом или одноразовой ссылкой.

---

## 5. Где хранить данные и где крутить логику

- **Вариант 1:** Всё на одном VPS: WireGuard + скрипты + БД + панель или бот-сервер (например, на том же VPS крутится Python-бот).
- **Вариант 2:** Бот или панель у тебя на ПК/другом сервере, VPS только для WireGuard; связь с VPS по SSH или по API на VPS.

Для «подписки» достаточно одной таблицы, например:

- `users`: id, name, telegram_id (если бот), public_key, allowed_ip, date_start, date_end, is_active, created_at.

Cron на той машине, где есть доступ к БД и к VPS (или к API на VPS), раз в день отключает пользователей с `date_end < today`.

---

## 6. Краткий вывод

| Задача | Решение |
|--------|--------|
| Установка WG | Инструкция в **WIREGUARD_SETUP.md** |
| Добавление пользователей без захода на сервер | Скрипты на VPS (add/remove peer) + вызов их из панели или бота (SSH или API) |
| Контроль срока подписки | БД с датой окончания + cron, который удаляет/отключает peer по дате |
| Удобный интерфейс | **Веб-панель** (полноценный доступ с ПК) или **бот** (быстро, из телеграма) |

Оба варианта (веб и бот) выполнимы; логика одна: БД подписок + скрипты на VPS + периодическая проверка срока. В этом репозитории можно дальше завести код панели или бота и скрипты для VPS.
