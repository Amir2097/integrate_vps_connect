# VPN (WireGuard) на VPS — установка и управление доступом

Репозиторий с инструкциями и (в перспективе) кодом для поднятия WireGuard на Ubuntu/Debian и управления доступом по подписке.

## Документация

| Файл | Содержание |
|------|------------|
| [docs/WIREGUARD_SETUP.md](docs/WIREGUARD_SETUP.md) | Установка WireGuard на Ubuntu/Debian, настройка сервера и клиентов |
| [docs/SUBSCRIPTION_SYSTEM.md](docs/SUBSCRIPTION_SYSTEM.md) | Система управления доступом: веб-панель или бот, подписки, добавление пользователей без захода на сервер |

**Скрипты:** [scripts/add-wg-client.sh](scripts/add-wg-client.sh) — добавление нового клиента и вывод QR-кода конфига одной командой на сервере (см. раздел 6.0 в WIREGUARD_SETUP.md).

## Веб-сервис (подписки, бот, админка)

Реализован первоначальный вариант для управления доступом и подписками:

- **FastAPI** — REST API для бота, админ-панель (Jinja2), JWT-логин.
- **Telegram-бот (aiogram 3)** — /start, «Подключиться к VPN», «Я оплатил», «Моя подписка», «Получить конфиг».
- **PostgreSQL** — пользователи, подписки, платежи, VPN-клиенты.
- **Планировщик** — раз в час помечает истёкшие подписки и отзывает доступ.
- Оплата вручную: пользователь нажимает «Я оплатил», администратор подтверждает в админке → создаётся VPN-клиент (скрипт), конфиг отправляется в Telegram.

Подробный запуск (локально и на VPS): **[README_WEB.md](README_WEB.md)**.

## Дальнейшие шаги

1. Поставить WireGuard по инструкции в `WIREGUARD_SETUP.md`.
2. Локально: создать venv, установить зависимости, настроить `.env` и PostgreSQL, запустить бэкенд и бота (см. README_WEB.md).
3. На VPS: развернуть бэкенд и бота, указать `WG_SCRIPT_PATH` и реквизиты БД/бота.
